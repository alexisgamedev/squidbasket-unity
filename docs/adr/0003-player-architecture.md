# Player, camera, and scoring architecture

The player is built as a state-object FSM (`PlayerStateController` owning `WalkingState`/`ShootingState`) rather than an enum-and-switch, since each state has meaningfully different per-frame behavior and enter/exit side effects (camera switch, Bullet Time, momentum handling). The controller owns all transitions and drives Movement/Shooting/camera directly, rather than those scripts polling shared state; it also owns Reset, which only fires during Walking, preserving the "no player-initiated cancel" rule from ADR-0002. Gameplay code (`PlayerStateController`, `WalkingState`, `RestartInputHandler`) reads input directly off the concrete `Squidbasket.Input.UnityInputPlayerInputSource` — an earlier `IPlayerInputSource` interface abstraction was removed as unnecessary indirection with only one real implementation and no concrete second-platform port planned; `Squidbasket.Runtime` references `Squidbasket.Input` directly (no Assembly Definition boundary enforces further decoupling).

Cameras are a deliberate deviation from `CLAUDE.md`'s stated intent for Cinemachine ("intended for shot-arc/follow camera framing") — we're hand-rolling `ThirdPersonCamera`/`FirstPersonCamera` classes driving a single shared `Camera` via a short positional/rotational lerp, instead of using Cinemachine's virtual cameras and blending. A future reader should not "fix" this by wiring Cinemachine back in without revisiting this decision.

Scoring is event-driven: a `HoopTrigger` fires a plain C# event (routed through a static `GameEvents` class) when the ball passes through, carrying Zone/points data that the `Ball` itself recorded at the moment of release. `ScoreSystem` is a dumb subscriber to that event and separately owns the Restart action (zeroing Score). The `Ball` also owns Retrieval (proximity pickup while loose). This keeps "was it a make" (physics), "how many points" (release-time data carried on the ball), and "total score" (ScoreSystem) as three independently owned concerns rather than any one system reaching into another's data.
